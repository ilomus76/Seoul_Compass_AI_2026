# 지도·장소 검색·길찾기 요구사항

이 문서는 서울 컴파스 AI에서 카카오맵 위에 검색 결과, 360도 방향 분석, 출발지에서 경유지를 거쳐 목적지까지의 이동 경로를 표시하기 위한 구현 요구사항이다.

## 1. 기능별 서비스 선택

기본 배경 지도는 카카오맵으로 한다. 장소 검색, 경로 조회, 외부 앱 실행에 사용할 서비스는 기능별로 정한다.

| 기능 | 카카오 중심 구성안 | 다른 서비스를 쓸 때 확인할 조건 |
| --- | --- | --- |
| 웹 지도 표시 | 카카오 지도 Web SDK로 배경 지도, 360도 분석 오버레이, 마커, 반경 원, 경로선 표시 | 네이버 지도 Web SDK 등. 웹 도메인 등록과 마커·도형·경로선 지원 확인 |
| 장소 검색 및 좌표 확인 | 카카오맵 REST API의 키워드·주소 검색 | 국내 장소 검색 지원, 좌표 반환, 검색 범위 및 호출 한도 확인 |
| 도보·버스·지하철 경로 조회 | 카카오맵 REST API로 도보·대중교통 구간 조회 | 이동수단별 서울 지역 지원과 거리·소요 시간·경로 좌표 제공 여부 확인 |
| 자동차 경로 조회 | 카카오모빌리티 자동차 길찾기 API | 네이버 클라우드 Directions 5 등. 경유지 제한과 경로 좌표 제공 여부 확인. Directions 5는 자동차 경로를 제공한다. |
| 외부 앱으로 길 안내 | 자동차 이동 시 사용자가 선택한 구간을 카카오내비에서 열기 | 공급자가 공식 지원하는 앱 링크나 웹 길찾기 링크 사용. 외부 앱이 전체 경유 일정 전달을 지원하지 않으면 구간별로 열기 |

- 현재 웹앱의 연동 범위는 카카오맵 표시, 장소 검색, 도보·대중교통 구간 조회다. 자동차 길찾기와 외부 내비 앱 실행은 확장 요구사항이다.
- 카카오내비 앱 버튼은 외부 앱의 길 안내를 시작하는 용도로 사용한다. 서울 컴파스 AI 화면의 경로선은 길찾기 API가 반환한 좌표로 그린다.
- 서로 다른 공급자를 조합할 때는 검색 결과와 경로 좌표를 선택한 배경 지도에 표시할 수 있는지 각 서비스의 이용조건을 확인한다.
- 이동수단별 연동 범위, 키 발급 방식, 호출 한도와 과금 조건을 확인한 뒤 도입할 서비스를 확정한다.

## 2. 여행 일정 질문과 검색 기준점

- 여행 일정 질문에서 날짜, 활동, 활동별 시각, 방문 순서, 검색 기준점, 반경, 지역 제한을 읽는다. “오늘”과 “내일”은 한국 시간 기준으로 해석한다. 사용자가 명시한 시각은 해당 활동에 연결하고, 뒤 활동에 같은 시각을 붙이지 않는다. “쯤”, “경”, “무렵”으로 표현한 시각은 희망 시각으로 처리한다.
- “관악산을 기준으로”처럼 질문에 검색 기준점이 있으면 해당 좌표를 360도 검색과 직선거리 계산에 우선 사용한다. 질문에서 별도 기준점을 지정하지 않으면 이름이 있는 첫 등산지나 고정 약속 장소를 일정에 맞춰 검색 중심으로 사용할 수 있다. 질문에서 지정한 기준점을 찾지 못하면 안내를 표시한다.
- 경로 출발지는 검색 기준점과 별도로 결정한다. “○○에서 출발”이라고 명시하면 그 장소를 사용한다. 별도 출발지 없이 이름이 지정된 산의 등산으로 일정이 시작하면 확인된 등산로 입구를 사용한다. 질문에서 출발지를 정할 수 없으면 아래의 출발지 입력란, 사용자가 허용한 현재 위치 또는 지도에서 선택한 위치를 사용한다.
- “오후 2시에 용산역에서 만나서 볼링”은 14:00 용산역 약속 이후 볼링으로 처리한다. 용산역을 검색 중심으로 사용하되 경로 출발지는 유지한다. “관악산을 기준으로 서울 5키로 반경”은 관악산에서 직선거리 5km 이내이면서 주소가 서울인 장소를 검색하는 뜻으로 해석한다. 서울 제한이 없는 질문은 반경 내 후보를 대상으로 한다.
- 카카오맵에서 받은 이름, 주소, 업종, 좌표를 확인해 활동에 맞는 후보를 표시한다. 등산은 해당 산의 등산로 입구를, 샤워는 목욕탕·사우나를, 술자리는 주점을, 볼링은 실제 볼링장 업종을 검색한다. 장소 이름에 검색어가 들어 있어도 업종이 맞지 않으면 후보에서 제외한다.
- 화면에 검색 기준점과 반경을 표시하고, 출발지가 다르면 지도에서 구분한다. 후보 목록과 지도 마커의 선택을 함께 갱신한다. 특정 활동의 후보가 없으면 해당 활동을 알려주고 확인된 일정과 지도 정보를 표시한다. 영업 여부를 확인할 수 없는 장소에는 확인 필요 상태를 표시한다.
- ‘AI 분석 시작’은 여행 일정 질문 입력란과 같은 영역에 둔다. 화면 폭이 480px보다 넓으면 입력란 오른쪽에, 480px 이하이면 바로 아래에 배치한다.

## 3. 카카오맵 위 360도 분석

- 웹앱의 360도 분석 영역에 카카오맵을 띄우고, 검색 기준점을 중심으로 같은 지도 위에 원, 부채꼴, 방위 라벨, 후보 마커를 표시한다.
- 정북을 위쪽, 동쪽을 오른쪽으로 표시한다. 정북 0°에서 시계 방향으로 45°마다 구역의 중심을 잡고, 각 중심에서 좌우 22.5°를 부채꼴 경계로 사용한다.
- 지도 위 방위 라벨은 북쪽부터 시계 방향으로 `N`(0°), `NE`(45°), `E`(90°), `SE`(135°), `S`(180°), `SW`(225°), `W`(270°), `NW`(315°)를 사용한다. 서버가 기존 한글 방향명을 반환하면 지도에 표시할 때 영문 약어로 변환한다.
- 검색 반경은 카카오 지도 SDK의 `Circle`로 표시한다. 예를 들어 5km는 5,000m로 전달한다. **원 테두리는 빨간색 `#E53935`**, 내부는 투명으로 하고 지도에 “검색 반경 5km”처럼 선택한 거리를 표시한다.
- 8개 부채꼴은 검색 기준점의 위·경도와 선택한 반경을 바탕으로 `Polygon`으로 그린다. 관심도 점수가 높은 방향일수록 채우기 농도를 높이되 배경 지도와 빨간 테두리가 읽히도록 반투명하게 유지한다. 방위 라벨은 `CustomOverlay`로 각 구역 중앙 방위에 배치한다.
- 후보 마커는 받은 위·경도에 고정한다. 검색 기준점이나 반경이 바뀌면 지도 위 원, 부채꼴, 영문 방위 라벨과 후보 마커를 함께 갱신한다. 지도 이동과 확대·축소 시 각 요소의 지리적 위치를 유지한다.

## 4. 이동 경로 표시

- 지도에 **출발지 → 1번 경유지 → 이후 경유지 → 목적지**를 순서대로 표시한다. 경유지가 없으면 출발지부터 목적지까지 한 구간을 그린다. 출발지와 목적지가 화면에 들어오도록 지도 범위를 조정한다.
- 도보나 대중교통은 연속한 방문 지점 사이의 구간별 경로를 조회한다. 자동차는 공급자가 경유지 순서를 보존하는 다중 경유지 조회를 지원하면 이를 사용할 수 있다.
- 응답에 경로 좌표가 있는 구간은 해당 좌표를 따라 지도에 실선으로 그린다. 구간별 이동수단, 거리, 예상 소요 시간을 표시한다. 검색 반경 계산에 쓰는 직선거리와 이동 경로 길이를 각각 표시한다.
- 목적지 후보나 이동수단을 바꾸면 카카오맵의 선택 마커와 이동선, 후보 목록과 일정표를 함께 갱신한다.
- 일부 경로를 가져올 수 없으면 해당 구간만 점선으로 표시하고 “직선 연결 · 이동 경로 미확인”이라고 안내한다. 예상 이동 시간을 확인할 수 없는 구간은 “소요 시간 미확인”으로 표시한다.
- 길찾기에서 얻은 이동시간을 선택한 경로의 일정표에 적용한다. 예상 도착이 요청 시각을 넘으면 일정표에 해당 활동과 차이를 표시하고 추천 카드에도 일정 충돌 여부를 표시한다. API가 요청한 출발 시각의 교통 정보를 제공하지 않으면 조회 시점 기준임을 표시한다.
- 등산 일정에서는 확인된 등산로 입구를 출발 또는 활동 지점으로 표시한다. 등산로 선형과 구간별 시간의 연동 기준은 [등산로·하산 예상 시각·영업시간 데이터](#7-등산로하산-예상-시각영업시간-데이터)를 따른다.
- 카카오내비에서 열기와 같은 외부 안내 버튼은 사용자가 눌렀을 때 실행한다. 앱을 열 수 없는 환경에는 지원되는 웹 길찾기 링크를 제공한다.

## 5. 키·권한·오류 처리

- 카카오디벨로퍼스에서 카카오맵 API를 활성화하고, **앱 → 플랫폼 키 → JavaScript 키 → JavaScript SDK 도메인**에 실제 웹 주소를 등록한다. 로컬 실행 주소가 `http://127.0.0.1:9200`이면 해당 주소를 등록한다.
- `KAKAO_JAVASCRIPT_KEY`는 웹 지도 표시용이며, `KAKAO_REST_API_KEY`는 서버의 장소 검색과 경로 조회에 사용한다. REST 키는 서버 환경변수로 관리한다. 실제 키는 Git에 올리지 않고, REST 키는 브라우저 응답과 로그에 포함하지 않는다.
- `.env`와 `.env.local`은 Git에서 제외한다. `.env.example`에서는 키 항목을 빈 값으로 유지한다. 현재 서버는 `.env`를 자동으로 읽지 않으므로, 로컬 파일에 저장한 값은 서버 실행 환경변수에 주입한다.
- 운영 환경에서 HTTPS를 사용하고, 사용자가 허용한 위치는 검색과 길찾기에 필요한 범위에서만 사용한다. 공급자 요청에는 경로 계산에 필요한 위치 정보만 전달한다.
- 지도 SDK 초기화 실패, 키 누락, API 제한, 검색 결과 없음, 경로 조회 실패를 각각 안내한다. 지도 로딩이 실패해도 가능한 범위에서 장소 목록과 360도 분석 또는 경로 요약을 표시한다. 샘플 데이터를 표시할 때는 데모임을 화면에 명시한다.

## 6. 완료 기준

| 입력 또는 상황 | 확인할 결과 |
| --- | --- |
| 오늘 오후 2시에 용산역에서 친구를 만나 볼링을 하고 싶다. 5km 근방에서 가능한 곳을 알려줘. | 날짜를 한국 시간 기준으로 해석한다. 용산역 약속은 14:00이고 볼링에는 같은 시각이 지정되지 않는다. 같은 카카오맵 위에 용산역 중심의 빨간색 5km 반경 원, 영문 방위 8개, 부채꼴과 반경 안의 확인된 볼링장 마커가 표시된다. |
| 내일 오전 10시에 관악산을 올랐다가 12시에 샤워, 오후 15시에 술, 18시에 볼링. 관악산 기준 서울 5km 반경에서 추천해 줘. | 출발지 입력란이 서울시청이어도 관악산 중심 5km를 분석한다. 등산로 입구를 출발점으로 삼고 서울 주소의 후보를 찾는다. 일정표에 등산 10:00 → 샤워 12:00 → 주점 15:00 → 볼링 18:00이 표시된다. |
| 관악산 일정에서 샤워 후보의 실제 도보 시간을 적용 | 요청 시각을 넘으면 샤워 시작 예상 시각과 지연을 표시한다. 다른 샤워 시설을 선택하면 동선, 도착 시각 및 일정 충돌을 다시 계산한다. |
| 관악산 코스별 상행·하행 데이터 연동 | 선택한 코스의 등산로 선형과 하산 출구를 지도에 표시한다. 상행·하행·휴식 시간과 하산 출구 이후 이동을 합쳐 12:00 샤워 가능 여부를 판단한다. 필수 구간 시간이 없으면 확인 필요로 표시한다. |
| 후보 업소의 운영시간 데이터 연동 | 방문 날짜와 체류 시간 전체를 영업 구간과 비교한다. 휴무·휴게시간·자정 이후 영업과 영업시간 데이터가 누락된 경우를 각각 처리한다. |
| 질문에 산 이름이 검색 기준점으로만 등장 | “관악산 기준으로 볼링장”은 관악산 주변의 볼링장 검색으로 처리한다. |
| 질문에 명시한 검색 기준점의 좌표 없음 | 기준점을 찾지 못했음을 표시한다. |
| 검색 반경을 5km에서 3km로 변경 | 빨간색 원과 부채꼴이 3km로 바뀌고, 후보와 방향 점수도 갱신된다. |
| 카카오맵 이동 또는 확대·축소 | 원, 부채꼴, 영문 방위 라벨, 후보 마커가 각 지리 좌표에 유지된다. 지도 위 북쪽은 `N`, 오른쪽 동쪽은 `E`로 표시된다. |
| 볼링장 후보를 선택하거나 변경 | 출발지 → 용산역 → 선택한 볼링장 순서가 카카오맵과 일정표에 표시된다. 선택을 변경하면 지도 마커, 후보 목록과 경로가 갱신된다. |
| 현재 위치 권한을 거부 | 주소 검색이나 지도 선택으로 출발지를 지정해 검색을 이어갈 수 있다. |
| 목적지 하나를 직접 검색 | 좌표가 확인된 목적지를 표시하고 출발지와 연결하는 한 구간의 경로를 그린다. |
| 반경 내 후보 없음 또는 한 구간의 길찾기 실패 | 후보가 없으면 검색 기준점과 반경을 유지한다. 경로 조회에 실패하면 해당 구간만 점선으로 표시한다. |
| JavaScript 키의 도메인 미등록 | 지도 대신 360도 방향 도표를 표시하고 키와 웹 도메인 설정을 확인하도록 안내한다. REST 검색이 동작하면 후보 목록과 경로 요약을 유지한다. |
| 카카오내비 실행 기능 도입 후 | 지원되는 환경에서 선택한 자동차 구간으로 내비 앱을 열 수 있다. 앱을 열 수 없는 환경에서는 지원되는 웹 길찾기 링크를 표시한다. |

## 7. 등산로·하산 예상 시각·영업시간 데이터

아래 항목은 공식 문서에서 제공 범위와 필드를 확인한 연동 후보이다. 관악산 구간별 API 응답과 개별 업소의 영업시간은 연동 전에 표본으로 검증한다.

### 7.1 등산로와 하산 시간

| 출처 | 제공 정보 | 적용 방안 |
| --- | --- | --- |
| [산림청 등산로 공간데이터](https://www.data.go.kr/data/3034022/fileData.do) · [산림청 필드 설명](https://kna.forest.go.kr/kfsweb/opda/dataMng/pblicDataPrusContView.do?pblicDataId=PBD0000041&tabs=3&mn=NKFS_06_08_02) | 산별 다운로드 파일에 등산로 선형, 주요 지점, 거리, 난이도, 상행 분 `PMNTN_UPPL`, 하행 분 `PMNTN_GODN`이 정의되어 있다. [산림청 개방 목록](https://www.forest.go.kr/kfsweb/kfi/kfs/trail/trailInformation.do?pblicDataId=PBD0000041&tabs=3&mn=NKFS_06_08_02&pageIndex=27&pageUnit=10)에 관악산이 포함된다. | **등산로 선형과 시간의 1차 출처.** 원본 좌표계와 데이터 기준일을 확인해 WGS84로 변환한다. 구간별 시작점·끝점과 상행·하행 방향을 대조한다. 파일의 통제·폐쇄 필드는 실시간 상태로 사용하지 않는다. |
| [국토교통부 등산로 WMS/WFS OpenAPI](https://www.data.go.kr/data/15057232/openapi.do) | 공공데이터포털에 등산로와 시설 등 공간정보를 제공하는 API로 등록되어 있다. | **실시간 조회 방식 후보.** 선형과 속성 조회에는 WFS를 검토한다. 관악산 구간의 실제 응답, 좌표계, 하행시간 포함 여부와 출처 표기 조건을 확인한 뒤 적용한다. |
| [서울관광재단 관악산 8코스 하이킹 맵](https://seoulhiking.or.kr/data/mountain_pdf/note_20250910183805443_01.pdf) · [서울시 관악산 등산로 안내](https://map.seoul.go.kr/smgis2/short/6PLur) | 코스별 출발지·도착지, 경유 지점, 거리와 소요시간을 확인할 수 있는 공개 안내 자료다. | 구간 연결과 상행·하행 방향을 대조하는 데 사용한다. 안내 시간은 자료에 명시된 출발지와 도착지에만 적용한다. |

- 선택한 산행 코스의 선형을 카카오맵에 표시하고, 입구·정상 또는 반환점·하산 출구를 구분한다. 상행과 하행에 같은 구간을 쓰더라도 각 방향의 시간값을 적용한다. 다음 장소로의 도보·대중교통 조회는 하산 출구에서 시작한다.
- 예상 하산 시각은 산행 시작 시각에 선택한 상행·하행 구간 시간과 휴식 시간을 더해 계산한다. 일부 시간값이 비어 있거나 구간을 연결할 수 없으면 “하산 시각 확인 필요”로 표시한다. 등산 시작 10:00과 샤워 시작 12:00 사이에는 산행, 휴식, 출구에서 샤워 장소까지의 이동이 모두 들어가야 한다.
- 예를 들어 [서울관광재단의 연주대 A 코스](https://seoulhiking.or.kr/data/mountain_pdf/note_20250910183805443_01.pdf)는 서울대 건설환경종합연구소에서 연주대 정상까지 약 1시간 30분이다. 10:00 출발이면 안내 시간 기준 정상 도착은 약 11:30이다. 12:00 샤워 가능 여부는 남은 하행과 이동시간을 확인해 판단한다.
- 입산 가능 여부는 [산림청 국가산불정보시스템](https://fd.forest.go.kr/ffas/)과 관할 지자체의 공고를 별도로 확인한다. 방문일에 통제된 구간은 추천에서 제외하고, 그날의 통제 여부를 확인하지 못한 경우에는 표시한다.

### 7.2 장소별 영업시간

| 출처 | 제공 정보 | 적용 방안 |
| --- | --- | --- |
| [카카오맵 REST API](https://developers.kakao.com/docs/ko/kakaomap/rest-api#search-by-keyword) · [영업시간 제공 범위 안내](https://devtalk.kakao.com/t/topic/144466) | 장소명, 주소, 좌표, 전화번호, `place_url`을 제공한다. 공개 장소 검색 응답에는 영업시간 필드가 없다. | 카카오맵으로 후보를 찾고, 자동 조회가 어려운 경우 장소 상세 링크나 전화번호로 확인할 수 있게 한다. |
| [Foursquare Places API](https://docs.foursquare.com/fsq-developers-places/reference/place-details) · [Place Match](https://docs.foursquare.com/fsq-developers-places/reference/place-match) | 장소 상세에 요일별 영업시간 `hours.regular`과 현재 영업 여부 `hours.open_now`가 정의되어 있다. 이름과 위치를 사용한 장소 매칭 기능이 있다. | **일반 업소 영업시간 보강 후보.** 사우나·주점·볼링장 표본에서 같은 지점을 찾는지, 영업시간이 실제로 반환되는지 확인한다. 카카오맵 병용, 표시·저장 조건, 과금은 도입 전에 확인한다. |
| [한국관광공사 TourAPI 국문 관광정보 서비스](https://www.data.go.kr/data/15101578/openapi.do) | 관광공사에 등록된 장소의 소개정보와 반복정보를 API로 제공한다. | 운영·이용 시간이 기재된 관광지와 시설의 보조 출처로 사용한다. 관악산 주변 일반 업소 전체의 영업시간을 수록한다고 가정하지 않는다. |
| [Google Places API (New)](https://developers.google.com/maps/documentation/places/web-service/reference/rest/v1/places) · [Google 지도 서비스 약관](https://cloud.google.com/maps-platform/terms/maps-service-terms#15-places-api-legacy-and-new) | 통상 영업시간 `regularOpeningHours`, 오늘을 포함한 7일간의 예외 반영 영업시간 `currentOpeningHours`를 문서화하고 있다. | Google 표준 약관의 타사 지도 병용 제한 때문에 현재 카카오맵 화면의 영업시간 공급자로 채택하지 않는다. |

- 보강 API 결과는 상호·지점명·주소·좌표로 대조한다. 다른 지점이거나 매칭이 불확실하면 시간을 가져오지 않고 “영업시간 확인 필요”를 표시한다.
- 한국 시간 기준 방문 예정일의 영업 구간과 도착·체류 종료 시각을 비교한다. 제공되는 경우 휴무·휴게시간·자정 이후 영업과 마지막 입장 또는 주문 시각을 반영한다. 조회 시점의 `open_now`만으로 미래 일정의 방문 가능 여부를 정하지 않는다.
- 시간 정보가 없거나 특정 날짜의 예외 영업이 확인되지 않으면 확인 상태와 출처를 표시한다. 우성사우나·왕빈자전통주막 관악산점·스매싱볼 사당점은 동일 지점 매칭과 영업시간 응답 여부를 검증하는 표본으로 사용한다.
