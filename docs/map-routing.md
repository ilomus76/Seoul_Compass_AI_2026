# 지도·장소 검색·길찾기 요구사항

이 문서는 서울 컴파스 AI에서 카카오맵 위에 검색 결과, 360도 방향 분석, 출발지에서 경유지를 거쳐 목적지까지의 이동 경로를 표시하기 위한 구현 요구사항이다.

2026-11-26 사용자 요청에 따라 대화에서 정리한 지도 관련 요구사항 22개를 대조하여 보완했다. 기존 `AGENTS.md`와 [추가 요청 원문](GyuHyeon.md)의 지도 관련 항목을 함께 참조하며, 아래 내용은 목표 요구사항이다. 실제 구현·검증 결과는 [개발 진행 상황](progress.md)에서 구분하여 확인한다.

## 1. 기능별 서비스 선택

기본 배경 지도는 카카오맵으로 한다. 장소 검색, 경로 조회, 외부 앱 실행에 사용할 서비스는 기능별로 정한다.

| 기능 | 카카오 중심 구성안 | 다른 서비스를 쓸 때 확인할 조건 |
| --- | --- | --- |
| 웹 지도 표시 | 카카오 지도 Web SDK로 배경 지도, 360도 분석 오버레이, 마커, 반경 원, 경로선 표시 | 네이버 지도 Web SDK 등. 웹 도메인 등록과 마커·도형·경로선 지원 확인 |
| 장소 검색 및 좌표 확인 | 카카오맵 REST API의 키워드·주소 검색 | 국내 장소 검색 지원, 좌표 반환, 검색 범위 및 호출 한도 확인 |
| 도보·버스·지하철 경로 조회 | 카카오맵 REST API로 도보·대중교통 구간 조회 | 이동수단별 서울 지역 지원과 거리·소요 시간·경로 좌표 제공 여부 확인 |
| 자동차 경로 조회 | 카카오모빌리티 자동차 길찾기 API | 네이버 클라우드 Directions 5 등. 경유지 제한과 경로 좌표 제공 여부 확인. Directions 5는 자동차 경로를 제공한다. |
| 외부 앱으로 길 안내 | 자동차 이동 시 사용자가 선택한 구간을 카카오내비에서 열기 | 공급자가 공식 지원하는 앱 링크나 웹 길찾기 링크 사용. 외부 앱이 전체 경유 일정 전달을 지원하지 않으면 구간별로 열기 |

- 현재 웹앱은 카카오맵 표시와 장소 검색, 선택 경로의 도보·자전거·자동차 선형 조회를 제공한다. 지하철·기차 선형은 ODsay 키 설정 시 조회한다. 상세 내용은 4.3절을 따른다.
- 카카오내비 앱 버튼은 외부 앱의 길 안내를 시작하는 용도로 사용한다. 서울 컴파스 AI 화면의 경로선은 길찾기 API가 반환한 좌표로 그린다.
- 서로 다른 공급자를 조합할 때는 검색 결과와 경로 좌표를 선택한 배경 지도에 표시할 수 있는지 각 서비스의 이용조건을 확인한다.
- 이동수단별 연동 범위, 키 발급 방식, 호출 한도와 과금 조건을 확인한 뒤 도입할 서비스를 확정한다.

## 2. 여행 일정 질문과 검색 기준점

- 출발지는 사용자가 동의한 현재 GPS 위치, 주소·장소명 검색, 지도에서 직접 위치 선택하는 세 가지 방식으로 지정할 수 있어야 한다.
- 검색 반경은 기본 5km이며 1·3·5·10km를 선택할 수 있어야 한다. 검색 대상은 음식점·카페·주점·숙박·주거·의료·체육·볼링·등산로·목욕탕 및 샤워시설·문화시설 및 행사·관광지·쇼핑·공원·버스정류장·지하철역과 기타 사용자 요청 업종으로 확장할 수 있어야 한다.
- 여행 일정 질문에서 날짜, 활동, 활동별 시각, 방문 순서, 검색 기준점, 반경, 지역 제한을 읽는다. “오늘”과 “내일”은 한국 시간 기준으로 해석한다. 사용자가 명시한 시각은 해당 활동에 연결하고, 뒤 활동에 같은 시각을 붙이지 않는다. “쯤”, “경”, “무렵”으로 표현한 시각은 희망 시각으로 처리한다.
- “관악산을 기준으로”처럼 질문에 검색 기준점이 있으면 해당 좌표를 360도 검색과 직선거리 계산에 우선 사용한다. 질문에서 별도 기준점을 지정하지 않으면 이름이 있는 첫 등산지나 고정 약속 장소를 일정에 맞춰 검색 중심으로 사용할 수 있다. 질문에서 지정한 기준점을 찾지 못하면 안내를 표시한다.
- 경로 출발지는 검색 기준점과 별도로 결정한다. “○○에서 출발”이라고 명시하면 그 장소를 사용한다. 별도 출발지 없이 이름이 지정된 산의 등산으로 일정이 시작하면 확인된 등산로 입구를 사용한다. 질문에서 출발지를 정할 수 없으면 아래의 출발지 입력란, 사용자가 허용한 현재 위치 또는 지도에서 선택한 위치를 사용한다.
- “오후 2시에 용산역에서 만나서 볼링”은 14:00 용산역 약속 이후 볼링으로 처리한다. 용산역을 검색 중심으로 사용하되 경로 출발지는 유지한다. “관악산을 기준으로 서울 5키로 반경”은 관악산에서 직선거리 5km 이내이면서 주소가 서울인 장소를 검색하는 뜻으로 해석한다. 서울 제한이 없는 질문은 반경 내 후보를 대상으로 한다.
- 카카오맵에서 받은 이름, 주소, 업종, 좌표를 확인해 활동에 맞는 후보를 표시한다. 등산은 해당 산의 등산로 입구를, 샤워는 목욕탕·사우나를, 술자리는 주점을, 볼링은 실제 볼링장 업종을 검색한다. 장소 이름에 검색어가 들어 있어도 업종이 맞지 않으면 후보에서 제외한다.
- 활동별로 조회한 장소를 최대 15개까지 군집에 반영하며, 경로 계산에는 우수 후보 군집을 최대 5개 사용한다. 실제 검색 결과가 부족하면 확인된 후보만 제공한다. 장소를 임의로 생성하지 않는다. 장소 목록과 지도 마커를 선택하면 해당 장소의 상세정보를 함께 확인할 수 있어야 한다.
- 화면에 검색 기준점과 반경을 표시하고, 출발지가 다르면 지도에서 구분한다. 후보 목록과 지도 마커의 선택을 함께 갱신한다. 특정 활동의 후보가 없으면 해당 활동을 알려주고 확인된 일정과 지도 정보를 표시한다. 영업 여부를 확인할 수 없는 장소에는 확인 필요 상태를 표시한다.
- ‘AI 분석 시작’은 여행 일정 질문 입력란과 같은 영역에 둔다. 화면 폭이 480px보다 넓으면 입력란 오른쪽에, 480px 이하이면 바로 아래에 배치한다.

### 2.1 문맥에 따른 중심 선택과 서울시청 자동 대체 금지

2026-11-26 사용자 요청: 분석할 때 항상 서울시청에서 시작하지 않고, 요청 문맥에 맞는 중심을 찾아 그 반경으로 검색한다.

1. “관악산 기준”, “명동 주변” 등 질문에 명시한 검색 기준점이 최우선이다.
2. 별도 기준점이 없으면 “서울역에서 출발” 같은 명시적 출발지를 기준으로 삼는다.
3. 출발지 지정도 없으면 이름이 있는 첫 산행 장소, 고정 약속 장소, 그 밖에 처음 언급한 장소 순으로 문맥을 해석한다. 단순히 주변 검색 기준으로 언급한 산을 등산 활동으로 추가하지 않는다.
4. 질문에 장소를 정할 근거가 없을 때만 사용자가 입력하거나 지도에서 선택한 위치 또는 동의한 현재 위치를 사용한다. 이전 질문에서 자동 추론한 중심을 새 질문의 수동 출발지처럼 재사용하지 않는다.
5. 명시한 기준점을 찾지 못했거나 같은 이름의 여러 지역이 있으면 확인을 요청한다. 서울시청이나 임의의 좌표로 대신 검색하지 않는다. 위치가 없는 상태에서 보이는 초기 지도는 분석에 사용된 위치가 아니다.
6. 실제 출발지는 질문의 명시적 출발지 → 첫 산행의 확인된 입구 → 사용자가 지정한 출발 위치 순으로 결정한다. 별도 출발 근거가 없으면 확인된 검색 중심에서 시작한다. 검색 중심과 출발지가 다르면 각각 표시한다.
7. 질문에 지정한 반경을 입력란보다 우선 적용하고, 없으면 입력란의 반경, 그마저 없으면 기본 5km를 사용한다. 지원하는 반경은 1·3·5·10km이며 다른 값은 사용자에게 확인한다.
8. 확인된 검색 중심과 반경을 주변 장소 검색, 360도 방향 분석, 밀집도와 경로 후보 선정에 동일하게 적용한다. 필수 활동의 후보가 부족해도 선택 반경을 임의로 늘리지 않고 후보 부족을 안내한다. 방향 구역의 탐색 확장과 반경 확장은 구분한다.
9. 지도 안내와 구조화 결과에는 검색 기준점, 선택 이유, 반경, 실제 출발지와 좌표 출처를 제공한다. 샘플 좌표를 썼다면 데모임을 알리고 실제 정보처럼 단정하지 않는다.

검증 예: “관악산 기준으로 3km 안에서 볼링”은 관악산 중심 3km, “서울역에서 출발해 명동 주변 1km 카페”는 서울역 출발·명동 중심 1km로 처리한다. “볼링을 치고 싶어”처럼 장소와 사용자가 지정한 위치가 모두 없으면 위치 확인을 안내한다.

### 2.2 목적지 미정 지역 추천과 활동·시간 조건

2026-11-26 사용자 승인: “내일 오전 10시 서울에 있는 산 등산, 12시 하산 후 수영, 15시 순대국 식사에 괜찮은 지역 추천”을 분석할 수 있도록 진행한다.

- 특정 산·역·출발지가 없고 서울 지역 추천을 요청하면, 단순 위치 누락으로 중단하지 않고 `region_discovery` 모드에서 지역 후보를 비교한다. 이름이 명시된 요청에는 기존 2.1절을 유지한다.
- 1차 구현은 서울의 산행으로 시작하는 일정을 대상으로 한다. 관악산·북한산·아차산·인왕산·불암산의 입구를 실제 장소 검색으로 조회하고, 서울 주소와 해당 산 이름·입구 정보를 확인한 결과만 사용한다. 최대 5개 산의 후보 중 상위 3개 지역을 보여주며 서울 전체의 최적 지역이라고 단정하지 않는다.
- 각 입구의 선택 반경 안에서 활동별로 최대 15개 시설을 찾아 군집화에 사용한다. 수영은 실제 수영장 업종을 확인하고 어린이 물놀이장·계절형 워터파크·용품 판매점은 일반 수영 후보에서 제외한다. 자유수영·성인 입장·운영시간은 별도 확인한다.
- “순대국/순댓국”은 필수 메뉴 조건으로 보존한다. 상호와 업종에서 확인되지 않는 일반 음식점으로 대체하지 않으며 당일 메뉴 판매 여부는 확인 필요로 표시한다.
- 예제는 등산 10:00 시작·12:00 종료의 사용자 지정 시간창, 수영은 하산 후 이동 가능한 12시 이후, 식사는 고정 15:00으로 해석한다. “12시에 수영”처럼 수영 시작을 직접 지정하면 고정시각을 유지하고 지연을 충돌로 표시한다.
- 수영·환복의 기본 90분과 식사의 기본 60분은 추정값으로 표시하고 사용자가 수정할 수 있게 한다. 사용자 지정 산행 시간창은 실제 코스 소요시간이 확인됐다는 의미가 아니다.
- 각 구간의 이동 추정과 여유시간을 도착시각에 포함한다. 체류시간·시각 수정 시 이후 일정을 다시 계산하고 고정시각 초과 분을 표시한다. 필수 장소 부족·시간 충돌·방문 조건 확인 필요 상태를 구분한다.
- 지역 카드에는 활동별 후보 수·누락 조건·시간표·확인사항·조회된 장소 상세 링크를 제공한다. 지역 선택 시 지도 중심·반경 원·마커·일정표를 함께 변경한다.
- 실제 영업시간·산행 상하행 시간·하산 출구·실제 이동 경로를 검증하지 못한 결과는 **검토용 일정**으로 표시한다. 미확인 경로는 점선으로 그리고, 비용·평점·혼잡도를 임의로 만들지 않는다. 지역 후보의 `verified_feasible`은 false로 유지한다.
- 기존 카카오 REST 키로만 조회하고 새 외부 라이브러리를 추가하지 않는다. 키가 없으면 실제 있는 샘플만 비교하며 수영장·식당을 만들어 완성된 경로로 표시하지 않는다. API 실패와 검색 결과 부족을 안내한다.

### 2.3 이름이 지정된 목적지·현재 위치 출발·서울 밖 검색

2026-11-26 사용자 승인: “10시에 소래산으로 지금 위치에서 발해서 12시에 내려와 수영하고 15시에 순대국”도 실제 검색과 일정 검증으로 연결한다.

- 특정 산 목록에만 의존하지 않는다. “소래산으로 … 내려와”, “문수산으로 … 하산”처럼 목적지와 뒤의 하산 문맥을 함께 해석해 생략된 산행 활동을 복원한다. 기준점으로만 언급한 산을 산행으로 추가하지 않는 기존 규칙은 유지한다.
- “위치에서 발해서”처럼 출발 문맥이 명확한 누락 표현만 제한적으로 “출발해서”로 보정하고 보정 사실을 안내한다.
- “지금/현재 위치에서”는 장소 이름이 아닌 출발 위치 참조로 관리한다. GPS 또는 사용자가 직접 선택한 출발 좌표와 목적지 좌표를 별도 필드로 유지한다. IP 추정 위치를 현재 GPS 출발지로 대체하지 않는다.
- 현재 좌표가 없어도 목적지 좌표를 확인한 뒤 주변 시설 검색은 계속한다. 출발 구간·전체 일정은 현재 위치 또는 수동 출발 위치를 적용한 뒤 계산한다. 브라우저 위치 동의는 사용자가 위치 적용 버튼을 선택하는 흐름에서 받는다.
- 이름이 지정된 목적지에도 기존 실시간 장소 검색을 연결한다. “서울 안/내/지역”, “서울에 있는 산” 등 검색 지역 제한이 없는 경우에는 서울 주소 필터를 강제로 적용하지 않고 목적지 반경 안에서 검색한다. “서울역 출발” 같은 출발지 이름은 서울 지역 제한을 의미하지 않는다.
- 지도용 좌표는 실제 키가 있으면 카카오 장소 조회를 우선하고, 실패 시 확인 가능한 샘플이 있을 때만 데모 안내와 함께 사용한다. 동명 장소가 서로 다른 지역에 있으면 임의로 확정하지 않는다.
- 산의 위치와 등산로 입구를 구분한다. 실제 조회된 입구가 있으면 입구 후보를 제시하고, 산 좌표만 확인되면 입구 선택 필요 상태로 표시한다. 실제 하산 출구와 코스 시간은 검증 전 확인 필요로 유지한다.
- “10시에 소래산으로 현재 위치에서 출발”의 10시는 출발 시각으로 표시한다. 첫 이동시간·여유시간을 뺀 12시까지의 산행 가능 시간창을 계산하고, 도착이 12시를 넘으면 충돌을 안내한다. 실제 산행 코스 소요시간이 확인된 것으로 표시하지 않는다. 명시적으로 등산 시작 10시를 지정한 요청은 출발 10시로 바꾸지 않는다.
- 위치 미적용·조회 실패·필수 시설 부족·시간 충돌 상태를 구분하고 현재 위치 적용 후 재분석 또는 수동 출발 좌표 입력을 안내한다. 새 라이브러리나 유료 API를 추가하지 않는다.

### 2.4 서울 역사 박물관·고궁·시장 먹거리

- “서울을 갈 건데”처럼 방문할 도시를 명시하고 역사 박물관으로 시작하는 일정은 서울을 검색 지역으로 적용한다. 구체적인 박물관이나 중심점이 없으면 서울 주소와 박물관 업종이 확인된 역사 박물관 후보 최대 3곳을 비교한다. 현재 위치나 이전 검색의 부천 좌표를 서울 일정의 검색 중심으로 재사용하지 않는다.
- “역사 관련 박물관”, “고궁”, “시장에서 음식을 즐기고”를 각각 서로 다른 순서의 활동으로 처리한다. 서울 주소·반경 기준을 모두 적용하고, 고궁 후보는 조회된 서울 고궁 본체에 한정한다. 주차장·부속 건물·고궁과 이름만 비슷한 업소는 제외한다.
- 날짜가 상대 표현과 명시 날짜로 충돌하면 명시 날짜를 우선하고 안내한다. “오전 10시 박물관”과 “12시에 박물관에서 나와서”는 10시 시작·12시 종료로 해석한다. 고궁은 12시 이후의 이동을 반영하고, 시장 시각은 선행 관람과 이동시간을 기준으로 계산한다.
- 시장은 확인된 전통시장 후보를 연결한다. 시장 지점 200m 안에서 조회된 음식점과 분식 가게를 최대 3곳 보여주고, 상호에서 확인할 수 있는 메뉴를 우선 표시한다. 메뉴·영업시간·예약 가능 여부와 방문일 실제 이동은 별도 확인이 필요하다.
- 자연어 해석은 문장 패턴과 조건 규칙을 사용한다. 추천 단계는 실제 장소 검색 결과를 주소·업종·좌표로 확인하고 기존 거리·일정 비교를 사용한다. 모델 학습은 수행하지 않는다.

### 2.5 문맥 모델로 일정과 검색 조건 해석

- 문맥 분석 모드는 입력에서 방문 지역, 출발지, 목적지, 날짜, 활동 순서, 고정·희망 시각, 장소 종류와 요청 메뉴를 추출한다. 활동마다 원래 요청 표현과 장소 검색어를 보존한다. 제공되지 않은 체류 시간은 추정으로 표시한다.
- 모델은 검색 조건을 구조화한다. 실제 장소명·좌표·업종은 카카오 장소 검색으로 확인한다. 지명이 모호하거나 좌표 또는 활동을 확인할 수 없으면 확인이 필요한 조건을 보여준다. 브라우저의 GPS 좌표와 여행 기록은 모델로 보내지 않는다.
- 시·군·구만 지정하면 방문 지역으로 사용한다. 구체적인 출발지가 없으면 첫 활동의 실제 후보를 기준으로 코스를 비교한다. 세부 검색어에 맞는 장소가 없으면 같은 지역과 시설 종류에서 다시 찾고, 해당 코스에 세부 조건 확인이 필요하다고 표시한다. 서울 고궁 활동은 궁궐 자체를 방문점으로 사용한다.
- 상점·놀이시설에는 제공되는 장소 링크와 공개 전화번호를 표시한다. 음식점은 한국관광공사 국문 관광정보에서 같은 시설을 확인했을 때만 소개정보의 공개 메뉴를 연결한다. 이름과 100m 이내 위치를 대조하며, 좌표가 없을 때는 같은 이름과 공개 전화번호를 확인한다. 두 공급자의 전화번호가 다르면 연결하지 않는다. 요청 메뉴와 일치하는 시설을 우선하고 확인이 안 된 메뉴에는 확인 필요를 표시한다.
- 문맥 모델 사용은 `AGENTS.md` 19.4의 외부 유료 API 사용 승인을 받은 후 `CONTEXT_LLM_ENABLED=true`로 활성화한다. 문맥 분석 API 오류는 화면에 표시한다. 비활성 환경의 기존 규칙 분석에는 별도 상태 표시를 둔다.

### 2.6 방문 지역 미지정과 경기 일정

- 방문할 도시·시설을 지정하지 않은 왕복 일정은 서울 시설을 검색한다. 사용자가 다른 지역이나 구체적인 장소를 지정하거나 현재 위치 주변 검색을 명시하면 해당 조건을 적용한다. 서울 기본 검색은 가능한 첫 활동의 실제 시설 후보를 비교한다.
- “식사하고 지금 위치로 돌아오기”의 현재 위치는 동의를 받은 복귀 지점이다. 출발지가 따로 없으면 같은 위치에서 출발한다. 복귀점이 서울 밖이어도 시설 검색 지역을 바꾸지 않으며, 귀환 이동은 별도 구간이다. 현재 위치가 없으면 적용을 안내한다.
- KBO 경기는 [TheSportsDB 일정 API](https://api.thesportsdb.com/documentation)에서 요청일과 앞뒤 하루를 조회한다. 카카오에서 구장 위치를 확인하고, 날짜·지역·구장·대진이 맞는 경기의 한국 시각을 경로 계산에 사용한다. 취소·연기 및 시작 시각 미확인 경기에는 확정 경로를 만들지 않는다.
- 데이터가 제공되지 않거나 API 조회에 실패하면 입력 날짜를 유지하고 [KBO 공식 경기 일정](https://www.koreabaseball.com/Schedule/Schedule.aspx) 또는 해당 주최 측 홈페이지 링크를 표시한다. 같은 날짜의 경기와 인접 날짜의 대안은 별도 날짜로 안내한다.
- [한일 드림 플레이어즈 게임 2026](https://dreamplayers.kr/)처럼 KBO 리그 밖의 행사는 주최 측 공지 출처를 표시한다. 고척스카이돔의 12월 4일 18:30 전야제와 12월 5일 14:00 본경기는 각각 별도 일정이다.

### 2.7 공개 업종 데이터 연동

- LLM은 활동 의미, 검색어와 유사 표현, 공개 업종명 후보, 시간 제약을 추출한다. 상호·업종 코드·사업자등록번호는 API 응답에서 확인되는 값만 사용한다. 같은 장소의 메뉴나 경기 시작 시각은 해당 공개 출처로 확인한다.
- 소상공인시장진흥공단의 상권정보 분류 목록을 조회해 업종명을 코드에 연결하고, 선택 반경과 지역에 속하는 상가를 후보에 포함한다. 카카오 결과와 상호·주소 또는 50m 이내 좌표가 일치하는 단일 지점은 한 장소로 병합한다. 양쪽 전화번호가 제공되면 서로 다른 번호를 가진 지점을 병합하지 않는다. 상가업소번호는 공공 상가 데이터의 식별자다.
- 상권정보 서비스가 미설정이거나 업종을 확인할 수 없으면 카카오 장소 조회 결과와 확인 상태를 표시한다. 세부 시설 특징·메뉴·영업시간을 확인하지 못한 장소에는 해당 확인 상태를 표시한다. 날짜·정확한 영업시간·취소 여부 등은 제공된 데이터 범위에서만 확정한다.

## 3. 카카오맵 위 360도 분석

- 웹앱의 360도 분석 영역에 카카오맵을 띄우고, 검색 기준점을 중심으로 같은 지도 위에 원, 부채꼴, 방위 라벨, 후보 마커를 표시한다.
- 정북을 위쪽, 동쪽을 오른쪽으로 표시한다. 정북 0°에서 시계 방향으로 45°마다 구역의 중심을 잡고, 각 중심에서 좌우 22.5°를 부채꼴 경계로 사용한다.
- 지도 위 방위 라벨은 북쪽부터 시계 방향으로 `N`(0°), `NE`(45°), `E`(90°), `SE`(135°), `S`(180°), `SW`(225°), `W`(270°), `NW`(315°)를 사용한다. 서버가 기존 한글 방향명을 반환하면 지도에 표시할 때 영문 약어로 변환한다.
- 검색 반경은 카카오 지도 SDK의 `Circle`로 표시한다. 예를 들어 5km는 5,000m로 전달한다. **원 테두리는 빨간색 `#E53935`**, 내부는 투명으로 한다. 2026-11-26 사용자 추가 요청에 따라 중앙의 “검색 반경 5km” 안내는 없애고, 원 위쪽 테두리 바로 안에 “반경 5km”처럼 선택한 거리를 배경 없이 빨간색으로 표시한다. 원 밖의 N 기호와 겹치지 않도록 하며, 반경 변경 및 컴패스·SVG 보기에도 같은 문구를 적용한다.
- 최초 표시와 검색 기준점·반경의 직접 변경 시 원 전체가 화면 안에 들어오도록 지도 범위를 맞춘다. 화면 크기 변경 시 사용자가 조정한 배율은 유지한다. 추천 목록에서 지역을 바꿀 때의 배율은 4.2절을 따른다. 지도와 컴패스 보기를 전환해도 원과 분석 표시가 정상적으로 복원되어야 한다.
- 8개 부채꼴은 검색 기준점의 위·경도와 선택한 반경을 바탕으로 `Polygon`으로 그린다. 관심도 점수가 높은 방향일수록 채우기 농도를 높이되 배경 지도와 빨간 테두리가 읽히도록 반투명하게 유지한다. 방위 라벨은 `CustomOverlay`로 각 구역 중앙 방위에 배치한다.
- 방향별 점수는 `AGENTS.md` 7장의 관심사 일치도·거리 적합성·품질 및 신뢰도·방문 가능성 기준으로 계산한다. 상위 3개 방향을 우선 탐색하되 실제 경로는 방향 구역 경계를 강제하지 않으며, 필수 활동을 충족하지 못하면 나머지 방향까지 탐색을 확장한다.
- 후보 마커는 받은 위·경도에 고정한다. 검색 기준점이나 반경이 바뀌면 지도 위 원, 부채꼴, 영문 방위 라벨과 후보 마커를 함께 갱신한다. 지도 이동과 확대·축소 시 각 요소의 지리적 위치를 유지한다.

### 3.1 지도 조작·마커·방위 가독성

2026-11-26 사용자 요청: 확대·축소 기능을 제공하고, 큰 마커와 한글 방위 글자가 지도 장소를 가리지 않도록 표시를 줄인다.

- 지도 오른쪽 위에 `+` 확대, `−` 축소, `전체` 검색 반경 전체 보기 버튼을 둔다. 카카오맵과 SDK를 사용할 수 없는 SVG 보기 모두에서 동작해야 한다. PC와 모바일에서 버튼을 선택할 수 있도록 최소 40px 크기를 유지한다.
- 카카오맵의 기본 큰 핀을 업종별 색상의 작은 점 마커로 바꾼다. 장소 점의 지름은 테두리를 포함해 약 12px이며, 투명한 24px 이미지 영역으로 선택 범위를 확보한다. 출발지·검색 기준점도 작은 점으로 구분한다.
- 장소 마커에 마우스를 올리거나 클릭·터치하면 장소명을 표시한다. 모든 장소명에 큰 배경 상자를 항상 띄워 지도 글자를 가리지 않는다.
- 방위는 `N`, `NE`, `E`, `SE`, `S`, `SW`, `W`, `NW`의 작은 영문 기호만 사용한다. 배경색·테두리·안쪽 여백을 없애고 검색 원 바깥에 둔다. 카카오맵은 기준점에서 반경의 1.10배 거리에 약 10px 글자로 표시한다.
- 영문 방위 기호와 방위 범례는 화면 자동 번역 대상에서 제외한다. 컴패스 및 SVG 지도에서도 원 밖의 작은 영문 기호를 유지하며, 방위 점수는 지도 글자에 덧붙이지 않는다.
- 확대·축소 중에도 지도 마커와 방위는 실제 지리 좌표를 유지한다. `전체` 버튼은 검색 반경이 모두 보이는 범위로 복원한다.

## 4. 이동 경로 표시

- 지도에 **출발지 → 1번 경유지 → 이후 경유지 → 목적지**를 순서대로 표시한다. 경유지가 없으면 출발지부터 목적지까지 한 구간을 그린다. 출발지와 목적지가 화면에 들어오도록 지도 범위를 조정한다.
- 추천 경로는 서로 다른 장소 조합을 최대 5개 표시하고 색상과 방문 번호로 구분한다. 사용자가 지정한 방문 순서와 고정 약속시간을 유지한다. 필수 활동이나 고정 약속시간을 충족하지 못하는 경로는 정상 추천 대상에서 제외하고 충돌을 안내한다.
- 도보나 대중교통은 연속한 방문 지점 사이의 구간별 경로를 조회한다. 자동차는 공급자가 경유지 순서를 보존하는 다중 경유지 조회를 지원하면 이를 사용할 수 있다.
- 응답에 경로 좌표가 있는 구간은 해당 좌표를 따라 지도에 실선으로 그린다. 구간별 이동수단, 거리, 예상 소요 시간을 표시한다. 검색 반경 계산에 쓰는 직선거리와 이동 경로 길이를 각각 표시한다.
- 목적지 후보나 이동수단을 바꾸면 카카오맵의 선택 마커와 이동선, 후보 목록과 일정표를 함께 갱신한다.
- 일부 경로를 가져올 수 없으면 해당 구간만 점선으로 표시하고 “직선 연결 · 이동 경로 미확인”이라고 안내한다. 예상 이동 시간을 확인할 수 없는 구간은 “소요 시간 미확인”으로 표시한다.
- 실제 경로 API로 검증하지 않은 경로를 실제 최적 경로라고 표시하지 않는다. 이동시간·거리·비용의 추정 여부와 비교 기준을 분명하게 안내한다.
- 길찾기에서 얻은 이동시간을 선택한 경로의 일정표에 적용한다. 예상 도착이 요청 시각을 넘으면 일정표에 해당 활동과 차이를 표시하고 추천 카드에도 일정 충돌 여부를 표시한다. API가 요청한 출발 시각의 교통 정보를 제공하지 않으면 조회 시점 기준임을 표시한다.
- 등산 일정에서는 확인된 등산로 입구를 출발 또는 활동 지점으로 표시한다. 등산로 선형과 구간별 시간의 연동 기준은 [등산로·하산 예상 시각·영업시간 데이터](#7-등산로하산-예상-시각영업시간-데이터)를 따른다.
- 카카오내비에서 열기와 같은 외부 안내 버튼은 사용자가 눌렀을 때 실행한다. 앱을 열 수 없는 환경에는 지원되는 웹 길찾기 링크를 제공한다.

### 4.1 시간대별 후보 군집과 지도 동선

2026-11-26 사용자 요청: 검색된 지점을 시간 관점에서 묶고, 군집화된 지점을 시간대별 동선으로 지도에 연결한다.

- 같은 활동에 해당하는 후보를 중심에서 50m 이내로 묶는다. 한 군집의 최대 지름은 100m이며 서로 다른 군집의 중심은 적어도 50m 간격을 유지한다. 서로 다른 활동은 가까워도 별개로 처리하고, 사용자가 고정한 장소 좌표는 그대로 쓴다.
- 후보가 여러 곳인 군집은 반경 50m의 옅은 영역과 후보 수로 표시한다. 각 군집 중심을 한 개의 경유지 후보로 삼아 추정 거리·이동시간과 지도 점선을 계산한다. 목록과 일정표의 장소명은 중심에 가장 가까운 실제 후보를 사용한다. 실제 목적지 좌표와 접근 가능 여부는 장소 정보에서 확인한다.
- 선택한 경로가 있으면 그 경로의 방문 장소와 일정표의 예상 시작시각을 우선한다. 활동별 대안 모두를 필수 방문점으로 연결하지 않는다. 방문 번호·시각·활동별 색상·진행 화살표로 요청 순서를 표시하고, 시간 충돌이 있는 활동에는 `!`와 확인 안내를 표시한다. 요청 순서와 고정 시각을 임의로 바꾸지 않는다.
- 출발 위치 미확보 등으로 시간표가 없으면 목적지 내부의 군집 중심을 연결한 **후보 동선**을 보여준다. 요청 시각·“이후”·종료시각·시각 미정을 구분하고 예상 도착·체류 시간을 생성하지 않는다. 출발 구간 미포함과 실제 방문 가능성 미검증을 안내한다.
- 필수 활동의 후보가 없으면 해당 단계의 방문점을 비우고, 누락된 단계를 건너뛰어 완성된 동선처럼 선을 잇지 않는다. 좌표가 같아 이동이 없는 구간의 선은 생략한다.
- 실제 길찾기 좌표가 없는 연결은 점선으로 표시하고 실제 길 미확인을 안내한다. 선택한 경로에는 진행 화살표와 방문 시간을 표시한다.
- 지도 위에 시간대 동선 표시 여부와 전체 동선·활동 시각별 필터를 제공한다. 특정 시각을 선택하면 그 활동의 군집·방문점과 그 활동으로 들어오는 연결을 표시한다. 기본 후보 마커와 검색 반경은 유지한다.
- 하단 시간 재생·슬라이더는 해당 시각의 방문점 및 이동 화살표를 강조한다. 경로·지역·방문 장소·활동 시각·체류시간 수정 시 지도 동선을 함께 갱신한다. 카카오맵과 SVG·컴패스 보기에 동일한 방문 번호·시간·색상·필터 기준을 적용한다.

### 4.2 경로 5개와 선정 이유

- 오른쪽의 “활동 후보 충족 … · 반경 …” 바로 아래에 “추천 1]”부터 조건에 맞는 장소 조합을 최대 5개 나열한다. 문맥 분석은 모든 지역의 코스를 함께 순위화한다. 기존 분석 모드에서는 후보 지역별 추천 번호를 표시한다.
- 추천별로 직선 연결 거리, 계산 가능한 이동시간과 일정 충돌, 일반 추천의 종합 점수, 방문 장소를 표시한다. 최단 거리·최소 이동 추정은 표시된 경로끼리 비교한다. 메뉴나 시설 조건은 조회된 장소에 근거하며 확인되지 않은 맛집 평판·영업시간·영화 상영 여부는 선정 이유로 단정하지 않는다.
- 일반 식사 후보에서 카페와 간식 업종을 제외한다. 거리순 식당 검색 첫 장이 가득 찼는데 반경 50m 군집이 3개 미만이면 같은 반경의 관련도순 결과와 필요 시 거리순 뒤쪽 결과 최대 2장을 확인한다. 활동당 조회 장소 15개를 고를 때 가까운 식사 군집마다 대표 후보를 먼저 확보한다.
- 지정하지 않은 식사 장소는 같은 일정 충돌 수의 후보 중 다른 식사 군집의 상위 경로를 먼저 보여준다. 1위는 기존 이동시간·거리 또는 점수 기준의 최상위 경로다. 다른 식사 군집이 소진되면 나머지 추천에 같은 군집이 다시 나올 수 있다.
- 방문 장소는 `장소명(요청 단어)`로 표시한다. 예를 들어 “서울역에서 출발해서 커피를 마시고 식사를 한 뒤 백화점에 가고 싶어요”의 목록에는 `서울역(서울역) → …(커피) → …(식사) → …(백화점)`이 표시된다. 분류에 사용한 표준 업종명 대신 입력에서 확인한 원래 표현을 우선한다.
- 카카오맵·컴패스·SVG 지도에서 추천 번호마다 같은 색을 사용한다. 공통 구간은 폭이 다른 점선을 포개 색을 구분한다. 오른쪽에서 추천을 선택하면 해당 경로의 시간·진행 방향·일정표를 표시한다. 시간대 필터는 선택 경로에 적용하고 전체 동선 보기에서 모든 색을 다시 표시한다.
- 출발 위치가 미확인인 경우 목적지 주변의 활동 조합과 직선 거리를 제공한다. 출발 이동과 시간표는 확인된 출발 좌표를 적용한 후 계산한다. 장소 조합이 5개보다 적으면 확인된 조합만 표시한다.
- 오른쪽 추천 및 지역 목록을 선택해도 마지막 지도 확대 배율을 유지한다. 같은 지역에서는 지도 위치도 유지하고, 다른 후보 지역을 선택하면 그 지역의 중심으로 이동한다. `전체` 버튼을 누르거나 검색 반경을 직접 변경할 때는 선택한 원 전체가 보이도록 맞춘다. 카카오맵과 SVG·컴패스에 같은 원칙을 적용한다.

### 4.3 이동수단별 실제 선형 표시

- 추천을 선택한 뒤 지도에서 이동수단을 고르고 **선택 경로의 실제 길 조회**를 누르면 경유 순서에 맞춰 공급자에 구간 좌표를 보낸다. 조회한 도로·노선 좌표는 추천 색상의 실선으로 그리며, 조회 전이거나 좌표가 없는 구간은 직선 추정 점선으로 표시한다. 여러 철도 좌표 구간에 빈 부분이 있으면 서로 연결하지 않는다.
- 도보·자전거·자동차는 [FOSSGIS의 OpenStreetMap 기반 OSRM](https://routing.openstreetmap.de/about.html)에서 모드별 좌표를 조회한다. 자동차 선은 차량이 이용할 도로의 방향과 선형을 나타낸다. 개별 차선 단위 위치는 공급자 응답에 포함되지 않는다. 도로 공급자에서 장소 좌표와 너무 멀리 떨어진 지점에 연결한 결과는 실선 표시에서 제외한다.
- 기차·지하철은 [ODsay 경로 검색 및 노선 그래픽 API](https://lab.odsay.com/guide/releaseReference?platform=web)가 제공하는 탑승 구간을 그린다. 서버에 유효한 `ODSAY_API_KEY`가 있어야 한다. 철도 선형에는 정류장·역까지의 접근 도보나 환승 통로가 포함되지 않는다. 조회한 선형과 기존 일정표의 이동 추정은 각각 표시한다.
- 실제 선형 조회는 선택한 추천 경로에 적용한다. 다른 추천을 선택해 해당 경로도 조회할 수 있다. 지도 배율과 시간대 필터는 유지한다. 공개 도로 서비스는 요청 간격을 최소 1초 이상으로 제한하고 지도에 출처와 수정 링크를 표시한다.

### 4.4 문맥 분석의 36방향 스캔과 대안 코스

- 확인된 사용자 출발 위치를 기준으로 0°, 10°, …, 350°를 중심으로 하는 겹치지 않는 폭 10° 구역 36개를 비교한다. 사용자가 방향을 지정하면 해당 구역부터 탐색한다. 출발지가 없는 지역 추천은 확인된 첫 활동 후보를 기준으로 비교한다.
- 각 구역에서 활동별 50m 군집을 시간 순서대로 연결한다. 고정 시간과 목적지를 지키는 코스가 단일 구역에서 성립하지 않을 때만 양옆의 인접 10° 구역을 합쳐 다시 시도한다. 북쪽에서는 350°·0°·10° 구역을 함께 쓸 수 있다.
- 방위는 경유 후보를 고르는 기준이다. 일정 순서에 맞춰 출발지 쪽으로 돌아오거나 옆 구역으로 이동할 수 있다. 출발점 50m 이내 군집과 출발·현재 위치 복귀점은 방위 범위 검사에서 제외한다.
- 방향별로 한 코스를 뽑아 중복을 제거하고, 메뉴 확인·세부 조건 확인 상태·예상 이동시간·거리로 비교한다. 상위 5개는 메인 지도에서 고유 번호와 색을 사용한다. 나머지 코스와 상위 5개에 포함되지 않은 공개 장소는 같은 탭의 `/alternatives`에서 확인한다. 5개보다 적으면 확인한 개수만 제공한다.
- 조회된 실제 도로와 철도는 공급자가 반환한 선형을 사용한다. 추천 순위의 이동시간은 직선거리 기반 추정이며 실제 길은 선택한 코스에서 조회한다.

## 5. 키·권한·오류 처리

- 카카오디벨로퍼스에서 카카오맵 API를 활성화하고, **앱 → 플랫폼 키 → JavaScript 키 → JavaScript SDK 도메인**에 실제 웹 주소를 등록한다. 로컬 실행 주소가 `http://127.0.0.1:9200`이면 해당 주소를 등록한다.
- `KAKAO_JAVASCRIPT_KEY`는 웹 지도 표시용이며, `KAKAO_REST_API_KEY`는 서버의 장소 검색과 경로 조회에 사용한다. REST 키는 서버 환경변수로 관리한다. 실제 키는 Git에 올리지 않고, REST 키는 브라우저 응답과 로그에 포함하지 않는다.
- `.env`와 `.env.local`은 Git에서 제외한다. `.env.example`에서는 키 항목을 빈 값으로 유지한다. 현재 서버는 `.env`를 자동으로 읽지 않으므로, 로컬 파일에 저장한 값은 서버 실행 환경변수에 주입한다.
- 운영 환경에서 HTTPS를 사용하고, 사용자가 허용한 위치는 검색과 길찾기에 필요한 범위에서만 사용한다. 공급자 요청에는 경로 계산에 필요한 위치 정보만 전달한다.
- 지도 SDK 초기화 실패, 키 누락, API 제한, 검색 결과 없음, 경로 조회 실패를 각각 안내한다. 지도 로딩이 실패해도 가능한 범위에서 장소 목록과 360도 분석 또는 경로 요약을 표시한다. 샘플 데이터를 표시할 때는 데모임을 화면에 명시한다.

| 카카오내비 실행 기능 도입 후 | 지원되는 환경에서 선택한 자동차 구간으로 내비 앱을 열 수 있다. 앱을 열 수 없는 환경에서는 지원되는 웹 길찾기 링크를 표시한다. |

- 입산 가능 여부는 [산림청 국가산불정보시스템](https://fd.forest.go.kr/ffas/)과 관할 지자체의 공고를 별도로 확인한다. 방문일에 통제된 구간은 추천에서 제외하고, 그날의 통제 여부를 확인하지 못한 경우에는 표시한다.

## 8. 장소 밀집도·이동수단·일정 변경

출처: [추가 요청 원문](GyuHyeon.md) 3·4·7·10번.

- 시간대별 활동과 검색 지역 전체의 관련 장소 데이터를 연결해 후보 목록을 정렬하고 장소 밀집도를 표시한다. 장소 수를 분석하는 밀집도와 관심사 충족도를 평가하는 방향 점수는 구분한다.
- 밀집 구역을 선택하면 사용자 플랜의 방문 순서대로 이동 경로를 표시한다.
- 도보·버스·지하철을 이동시간·교통비·혼잡도 기준으로 비교하고 추천 순서의 목록에서 선택할 수 있게 한다. 확인되지 않은 혼잡도나 비용은 추정치 또는 확인 필요로 표시한다.
- 장소별 가격·영업시간·시간별 혼잡도를 후보 선택에 활용한다. 영업시간 판단은 7.2절을 따른다.
- 일정의 시간·장소·이동수단 변경 또는 활동 취소 시 관련 마커·이동선·후보 목록·일정표를 함께 갱신하고 이후 도착시간과 충돌을 재계산한다. 필수 활동의 취소와 고정 약속시간 변경은 사용자가 명시적으로 선택한 경우에만 반영한다.

출처: [추가 요청 원문](GyuHyeon.md) 8·9·14번. `AGENTS.md` 12.4절의 단계별 범위를 따른다.

- 사용자가 위치 접근에 동의한 경우 현재 위치를 지도에 표시하고, 사용 중인 화면에서 위치 갱신을 시작·종료할 수 있어야 한다. 위치 권한을 거부하거나 위치를 얻지 못하면 수동 출발지 설정으로 이어갈 수 있어야 한다.
- 다양한 추천 경로를 지도에 표시하고 3D 화면에서 이동 경로를 시뮬레이션할 수 있어야 한다.
- 도보·대중교통 이동을 지원하는 실제 3D 내비게이션을 목표로 하며, 시뮬레이션과 실제 위치 기반 길 안내의 제공 여부를 구분한다.
- 동행인이 동의한 경우 동행인의 GPS 위치를 지도에 표시하고, 경로 이탈 또는 길을 잃은 상황에서 위치와 경로를 확인해 도움을 줄 수 있어야 한다.
- 동행인 위치 공유는 인증·사용자별 접근 제어·서버 저장소가 필요한 후속 단계로 관리한다. 24시간 MVP에 백그라운드 GPS 추적을 포함하지 않으며, 위치 정보는 사용자 동의 범위에서 처리한다.

## 10. 날씨·안전 정보·모바일 지원

출처: [추가 요청 원문](GyuHyeon.md) 5·11·12·15·16번 및 `AGENTS.md` 11장.

- 여행 날짜와 장소의 날씨를 분석해 실내·실외 활동 선택에 반영하고, 우산·양산·수분 섭취·따뜻한 옷·안전사고 주의 등 상황에 맞는 안내를 제공한다.
- 해당 지역의 사고 발생 위치와 위험구역을 지도에 표시하고 안전한 일정 선택을 지원한다. 실제 자료와 데모 자료를 구분하고 확인되지 않은 위험 정보를 실제 현황으로 표시하지 않는다.
- 주변 경찰서·소방서 등 도움 시설을 지도와 목록에 제공하고, 사용자가 선택해 긴급 연락을 할 수 있게 한다. 자동 신고 또는 위치 전송으로 처리하지 않는다.
- 등산·체육·야간·이동 등 활동과 환경에 맞는 안전사고 예방 지침을 제공한다.
- 스마트폰과 PC 모두에서 지도·반경 원·방위 라벨·장소 선택·경로·일정표를 사용할 수 있어야 한다. 화면 크기에 맞춰 지도와 입력·결과 영역을 배치한다.
- 지도·검색·경로 조회 오류 시 처리는 5절을 따른다. 지도 로딩 실패 시 가능한 목록과 360도 분석·경로 요약을 유지한다.
