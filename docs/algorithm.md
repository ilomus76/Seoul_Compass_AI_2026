# 알고리즘 요약

## 자연어 분석과 서울 역사 일정

- 문맥 분석 모드에서 LLM이 활동, 날짜, 시각, 지역, 검색어와 공개 업종명 후보를 구조화한다. 서버는 카카오와 소상공인시장진흥공단의 실제 카테고리·좌표를 대조한다. 기존 분석 모드는 문장 패턴을 사용한다.
- 확인된 장소를 업종·주소·반경으로 거르고 거리와 일정 제약을 계산해 경로를 비교한다. 맛 관련 요청은 시장 주변 업소와 상호에서 확인되는 메뉴 후보로 제시한다. 별도의 머신러닝 학습이나 맛 점수 추정은 수행하지 않는다.

## 360도 방향 분석

문맥 분석 모드는 실제로 조회한 장소를 시간대별 50m 군집으로 묶는다. 사용자 출발지를 중심으로 폭 10°의 구역 36개를 비교한다. 각 구역에서 코스가 성립하지 않을 때 양옆 10° 구역의 군집을 함께 탐색한다. 이동 방향을 강제하지 않고 활동 순서와 고정 시간을 유지한다. 중복 제거 후 상위 5개를 메인 지도에, 나머지는 추가 코스 화면에 표시한다. 경로 검색 구역과 아래 8개 지도 표시 구역은 독립적으로 계산한다.
- 거리: Haversine 공식(직선거리, 1차 필터에만 사용)
- 방위각: `atan2(sinΔλ·cosφ2, cosφ1·sinφ2 - sinφ1·cosφ2·cosΔλ)`, 북=0°, 시계방향
- 8구역: 각 45도, `index = int((bearing + 22.5) // 45) % 8`

## 장소 점수
`P = 0.40M + 0.25D + 0.20Q + 0.15V` (가중치 합 1로 정규화)
- M 관심사 일치, D 거리 적합, Q 품질/신뢰도, V 방문 가능성
- 정보가 없는 항목은 임의 점수를 만들지 않고 신뢰도를 낮춘다.

## 방향 점수
`S = 0.7A + 0.3C` (A 상위 후보 평균 점수, C 필수 관심사 충족률). 후보 없으면 0점.

## 일정 검증
`도착 = 이전 종료 + 이동시간`, `시작 = max(도착, 방문가능시작)`, `종료 = 시작 + 소요시간`.
고정 약속 시간을 초과하면 충돌 정보를 반환하고 사용자의 승인 없이 시간을 바꾸지 않는다.
이동시간은 직선거리 기반 추정치(도보 5km/h)이며 실제 경로 API 값이 아니다.

## 경로 최적화
활동별 조회 후보 최대 15개 → 반경 50m 군집 중 최대 5개 선정 → 순서 유지 Beam Search(폭 5) → 서로 다른 군집 조합 최대 5개.
일반 추천은 일정 조건을 통과한 조합을 종합 점수로 정렬한다. 지역 검토용 일정은 충돌 수·이동 추정·직선 거리 순으로 비교하며, 출발 위치가 없으면 목적지 내부의 직선 거리를 비교한다.

지정하지 않은 식사 활동을 지나면 식사 군집마다 상위 경로를 최대 5개씩 보존한다. 마지막에는 일정 충돌 수가 같은 결과 중 서로 다른 식사 군집의 최상위 경로를 먼저 표시한다. 이 방식은 이동시간이나 거리만으로 중간 후보를 잘랐을 때 식사 장소 하나가 추천을 독점하는 문제를 줄인다.
`R = 0.35U + 0.25T + 0.20C + 0.20Q`. 필수 활동 후보가 없으면 반경을 2배·4배·20km로 확장하되, 존재하지 않는 장소는 생성하지 않는다.

## 시간대별 지도 동선
- 상세 요구사항은 `map-routing.md` 4.1절을 따른다. 활동마다 Haversine 거리 반경 50m 안에 가장 많은 후보가 있는 점을 찾아 묶고, 남은 후보에 같은 방식을 반복한다. 모든 후보가 여전히 50m 안에 있고 다른 군집 중심과 50m 이상 떨어질 때 군집 중심을 평균 좌표로 옮긴다.
- 경로 계산과 지도는 군집 중심을 사용한다. 목록과 일정표에는 그 중심에서 가장 가까운 실제 장소명을 표시한다. 시간표가 없으면 목적지 내부 군집 중심 간 직선거리로 후보 동선을 비교한다.
- 활동 순서를 유지해 인접 방문점만 연결한다. 누락된 활동을 건너뛰거나 동선에 모든 대안 후보를 넣지 않는다. 같은 좌표 사이의 선은 생략하고, 시간대 필터는 선택 활동과 해당 활동으로 들어오는 구간에 적용한다.
- 백엔드의 군집 좌표를 프런트엔드 `journey.js`에서 사용한다. 실제 길찾기 정보가 없는 선은 점선으로 표시한다.
